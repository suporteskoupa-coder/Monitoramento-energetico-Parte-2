Vamos desmistificar isso de forma bem visual. O "pulo do gato" aqui é entender que o sensor SCT-013 imita o comportamento da rede elétrica: ele gera uma mini onda alternada que vai para o lado positivo e para o lado negativo.

O problema é que o pino do ESP32 é como uma parede: **abaixo de 0V ele quebra (queima) e acima de 3.3V ele também quebra.**

---

### O Problema: Sem o circuito (Risco de queimar)

Imagine o gráfico da tensão que sai do sensor puramente. Se ele estiver lendo uma corrente que gera uma onda de 1V de pico, o sinal gerado vai ser:

* **Pico Positivo:** $+1\text{V}$
* **Pico Negativo:** $-1\text{V}$

Se você ligar direto no ESP32:

* Quando a onda estiver em $+1\text{V}$, o ESP32 lê tranquilamente (pois está entre $0\text{V}$ e $3.3\text{V}$).
* Quando a onda inverter e for para **$-1\text{V}$**, essa tensão negativa vai forçar a corrente a fluir pelo pino do ESP32 no sentido errado, danificando os componentes internos (os diodos de proteção e os transistores do ADC).

---

### A Solução: O circuito de Deslocamento (DC Bias)

Para resolver isso, nós fazemos um "truque" matemático e elétrico. Criamos uma linha de referência que não é o $0\text{V}$ (GND), mas sim **$1.65\text{V}$** (que é exatamente a metade de $3.3\text{V}$).

Fazemos isso usando dois resistores iguais ligados em série entre o $3.3\text{V}$ e o GND (um divisor de tensão).

Em vez de aterrar um dos fios do sensor no GND, nós ligamos esse fio nesse ponto de $1.65\text{V}$. Veja o que acontece com a matemática da onda:

* Se o sensor estiver em **$0\text{V}$** (sem medir nada), o ESP32 vai ler:
$$1.65\text{V} + 0\text{V} = 1.65\text{V}$$


* Quando o sensor atingir o pico positivo de **$+1\text{V}$**, o ESP32 vai ler:
$$1.65\text{V} + 1\text{V} = 2.65\text{V}$$


* Quando o sensor atingir o pico negativo de **$-1\text{V}$**, o ESP32 vai ler:
$$1.65\text{V} + (-1\text{V}) = 0.65\text{V}$$



---

### Resumo Visual do Sinal

Olha como o sinal se transforma antes de entrar no ESP32:

```text
Sem o circuito (Sinal Puro do Sensor):
  +1.0V  ---/\-------/\---  <- Ok para o ESP32
   0.0V  ---|--\-----/--|--  
   -1.0V  ------- \_/ -------  <- PERIGO: Tensão negativa queima o pino!

Com o circuito (Sinal Deslocado / "Flutuando" em 1.65V):
  +3.3V  -------------------  <- Limite Máximo do ESP32
  +2.65V ---/\-------/\---  <- Pico máximo atingido (Seguro!)
  +1.65V ---|--\-----/--|--  <- Novo "Zero" (Onde a onda começa)
  +0.65V ------- \_/ -------  <- Pico mínimo atingido (Ainda acima de 0V, Seguro!)
   0.0V  -------------------  <- Limite Mínimo do ESP32 (GND)

```

No código do seu ESP32, a função `analogRead()` vai ler valores que oscilam entre esses $0.65\text{V}$ e $2.65\text{V}$. Depois, via software, você só precisa subtrair o valor correspondente a $1.65\text{V}$ para reconstruir a onda original e calcular a corrente real.

Deu para clarear como esse circuito funciona como uma "almofada" de segurança para o microcontrolador?



Isso é feito **no Hardware** (com componentes físicos) **E** complementado **no Código** (via software). É um trabalho em equipe entre os dois.

Se você fizer apenas no código, o ESP32 queima antes mesmo de rodar a primeira linha, porque a tensão negativa física vai entrar no pino.

Aqui está exatamente a divisão de tarefas:

---

### 1. A Parte do Hardware (O Protetor Físico)

Antes do fio do sensor encostar no pino do ESP32, você precisa montar um pequeno circuito em uma **protoboard** (ou placa de circuito).

Você vai usar:

* **2 Resistores iguais** (geralmente de $10\text{ k}\Omega$ ou $100\text{ k}\Omega$) ligados entre o pino de $3.3\text{V}$ e o $GND$ do ESP32. O ponto bem no meio deles vira o seu "falso zero" de $1.65\text{V}$.
* **1 Capacitor** (geralmente de $10\ \mu\text{F}$) para manter essa tensão de $1.65\text{V}$ bem estável e sem ruídos.
* **O Sensor:** Um fio do jack do sensor vai nesse ponto de $1.65\text{V}$ e o outro fio vai direto para o pino analógico do ESP32 (ex: `GPIO34`).

> **O que o hardware faz:** Ele empurra a onda fisicamente para cima para que ela nunca fique negativa.

---

### 2. A Parte do Código (O Tradutor)

Agora que o hardware salvou a vida do ESP32, o pino analógico vai ler valores que ficam flutuando ao redor de $1.65\text{V}$.

Se você não mexer no código, o ESP32 vai achar que está passando corrente mesmo quando tudo estiver desligado (já que $1.65\text{V}$ não é zero para o conversor analógico-digital).

**O que você faz no código (exemplo em C++/Arduino):**

1. Você lê o pino usando `analogRead(PINO)`. O ESP32 transforma a tensão em um número de `0` a `4095`.
2. Como $1.65\text{V}$ é exatamente a metade de $3.3\text{V}$, o valor lido quando o sensor estiver "em silêncio" será por volta de `2048`.
3. No seu código, você **subtrai** esse valor central para que a onda volte a ter o "zero real" na memória do código.

```cpp
int valorLido = analogRead(GPIO_SENSOR);
// Subtrai o deslocamento (offset) de 1.65V (2048 em formato digital)
int ondaReal = valorLido - 2048; 

```

A partir daí, se o resultado de `ondaReal` for positivo (ex: `+500`), significa que a onda estava na parte de cima; se for negativo (ex: `-500`), estava na parte de baixo. O código reconstrói a onda perfeitamente e calcula o consumo em Watts de forma segura.

Ficou claro como os dois se complementam? O hardware protege e o software calcula!


Aqui está a lista exata dos componentes físicos que você vai precisar e a estrutura do código para colocar isso para rodar.

---

## 1. Os Componentes (Hardware)

Para montar o circuito na protoboard, você vai precisar de:

* **1x Sensor SCT-013** (Se for o modelo com saída em corrente, como o *SCT-013-000*, você precisará de um **Resistor de Burden** adicional de $22\ \Omega$ a $62\ \Omega$, dependendo do cálculo. Se for o modelo com saída em tensão, como o *SCT-013-030*, não precisa desse resistor extra).
* **2x Resistores de $10\text{ k}\Omega$ ou $100\text{ k}\Omega$** (Devem ser idênticos. Eles farão o divisor de tensão para criar os $1.65\text{V}$).
* **1x Capacitor Eletrolítico de $10\ \mu\text{F}$** (Para filtragem e estabilização do sinal).
* **1x Conector Jack P2 Fêmea** (Para conectar o plugue do sensor SCT-013 de forma limpa na protoboard).
* **1x Placa ESP32** e cabos jumpers para conexões.

---

## 2. O Código (Software)

A forma mais eficiente e precisa de ler esse sensor no ESP32 sem precisar reinventar a roda matemática (como o cálculo de raiz quadrada média, o RMS) é utilizando a biblioteca **EmonLib**, que é o padrão de mercado para isso.

### Passo 1: Instalar a Biblioteca

No seu ambiente de desenvolvimento (Arduino IDE ou VS Code/PlatformIO), procure e instale a biblioteca chamada **EmonLib** (de Trystan Lea).

### Passo 2: O Código-Fonte

Este código faz a leitura no pino analógico, remove os $1.65\text{V}$ (offset) automaticamente via software e calcula a corrente RMS real.

```cpp
#include "EmonLib.h"

// Cria uma instância do objeto de monitoramento
EnergyMonitor emon1;

// Define o pino analógico que você vai usar no ESP32
// Certifique-se de usar um pino do ADC1 (como GPIO 34, 35, 32, 33, 36, 39)
// Evite o ADC2, pois ele para de funcionar quando o Wi-Fi está ligado.
const int PINO_SENSOR = 34;

// Fator de calibração (Varia conforme o modelo do sensor e resistor de burden)
// Para o SCT-013-030 (saída em tensão), comece com ~30. 
// Para o SCT-013-000 com resistor externo, o cálculo muda.
const float FATOR_CALIBRACAO = 30.0; 

void setup() {
  Serial.begin(115200);
  
  // Configura a resolução do ADC do ESP32 para 12 bits (0 a 4095)
  analogReadResolution(12);
  
  // Inicializa a EmonLib: (Pino Analógico, Fator de Calibração)
  emon1.current(PINO_SENSOR, FATOR_CALIBRACAO);
}

void loop() {
  // Faz a amostragem da onda AC. 
  // 1480 é o número de amostras (padrão estável para capturar os ciclos de 60Hz)
  double correnteRMS = emon1.calcIrms(1480);
  
  // O ESP32 pode pegar pequenos ruídos elétricos mesmo sem nada ligado.
  // Filtro simples para zerar ruídos fantasmas abaixo de 0.05A
  if (correnteRMS < 0.05) {
    correnteRMS = 0.0;
  }

  // Calcula a potência aparente estimada (Corrente * Voltagem da sua rede)
  // Altere para 220.0 se a sua região for 220V
  double potenciaEstimada = correnteRMS * 127.0; 

  // Exibe os dados no Monitor Serial
  Serial.print("Corrente: ");
  Serial.print(correnteRMS, 2); // 2 casas decimais
  Serial.print(" A | Potencia Estimada: ");
  Serial.print(potenciaEstimada, 1);
  Serial.println(" W");

  // Aguarda 2 segundos antes da próxima leitura
  delay(2000);
}

```

### Como calibrar?

O valor `FATOR_CALIBRACAO` (que deixei como `30.0`) pode precisar de um ajuste fino. O ideal é ligar uma carga conhecida na tomada (um secador de cabelo ou uma lâmpada cuja potência você saiba), medir com um alicate amperímetro real ou ver o valor esperado no código e ir alterando esse número levemente para cima ou para baixo até que o valor exibido na tela combine perfeitamente com a realidade do seu equipamento.
